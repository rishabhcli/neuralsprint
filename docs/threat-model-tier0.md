# Tier 0 Threat Model: Local Foundation and Development Control Plane

- **Schema version:** 1
- **Reviewed:** 2026-08-10
- **Scope:** the static foundation surface, loopback services on ports 4210–4213, generated smoke fixtures, `.dev/` process state, and repository verification commands
- **Explicitly excluded:** PDF ingestion and user documents, because no such runtime path exists in Tier 0
- **Security posture:** not yet in production; this model authorizes no document-safety claim

## Assets and security properties

| Asset                                 | Required property                                                                                                                                               |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Sibling agents and host processes     | No command may signal a process that this repository did not start and revalidate.                                                                              |
| Exclusive port block                  | Only `127.0.0.1:4210`–`4213` may be allocated; 4214–4219 must remain free until deliberately assigned.                                                          |
| Repository authority and build inputs | A symlink, foreign working directory, mutable dependency range, or untracked cache may not silently become release input.                                       |
| PID records and owner nonces          | Records must be repository-local, mode-restricted, schema-validated, atomically created, and corroborated against the live command and listener before use.     |
| Foundation UI                         | It must not accept document bytes, imply a green verdict, load a remote asset, or create an analytics/network egress path.                                      |
| Synthetic fixture corpus              | Only deterministic generated bytes matching the committed manifest contract may be served. Paths must not escape the corpus root.                               |
| Evidence                              | An artifact must name its generator and seed, avoid credentials and host-specific paths, and never upgrade working-tree output into clean-checkout or CI proof. |

Owner nonces are process-ownership corroboration, not credentials or an authentication boundary against another process running as the same operating-system user. They must still never be written to service logs or committed evidence.

## Trust boundaries and entry points

1. **Loopback HTTP:** any local process, and potentially a hostile web page reaching loopback, can request the Vite, preview, fixture, liveness, readiness, or control routes.
2. **Process table and `.dev/pids/`:** lifecycle commands translate filesystem records and process metadata into targeted shutdown authority.
3. **Fixture URLs:** an HTTP path selects a generated PDF beneath `.dev/tmp/fixture-corpus/`.
4. **Package and build graph:** `npm ci`, platform-specific optional binaries, Vite transforms, and Playwright browser binaries execute third-party code during development and CI.
5. **Browser runtime:** built JavaScript and CSS execute locally; future document bytes are not present in this tier.
6. **Evidence generation:** command output crosses from a mutable local run into committed or CI-retained artifacts.

## Threats, controls, and verification

| ----- | ----------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| T0-01 | A foreign listener impersonates an owned service or causes a framework to select another port.                                | Exact `ports.env`; strict ports; `lsof` PID/address inventory; typed repository/service/port readiness; fail closed on every foreign reserved-block listener.                                                                                                          | `npm run dev:preflight`; `npm run dev:health`; development-health contract tests.                                                             |
| T0-02 | A stale or reused PID is signalled.                                                                                           | PID schema plus repository root, service, port, 256-bit nonce, live command fingerprint, exact listener PID/address, and revalidation before each shutdown escalation. No name-based or broad kill command exists.                                                     | Integration test `refuses to kill a foreign allocated-port listener and restores owned health`; `npm run dev:down`.                           |
| T0-03 | A malicious local web page sends a shutdown request.                                                                          | Shutdown requires a non-simple custom header containing the per-process nonce; the fixture server has an explicit origin allowlist; the control route binds only to loopback. The nonce is never rendered into the app.                                                | Integration test `refuses missing and incorrect control nonces without changing readiness`; lifecycle down exercises the authenticated route. |
| T0-04 | A crafted fixture URL reads an arbitrary local file.                                                                          | Decode once; require one manifest-allowlisted basename ending in `.pdf`; preload verified bytes into memory; return typed 400/404 responses without local paths.                                                                                                       | Fixture traversal/method integration test plus semantic fixture readiness hash check.                                                         |
| T0-05 | An oversized, hanging, redirected, or wrong-content readiness response produces a false green.                                | Manual redirects, abort deadlines, byte ceilings, strict content types, exact service identity, named semantic checks, and reserved-port inspection.                                                                                                                   | `scripts/lib/readiness-probes.mjs`; `evidence/dev-health.json`.                                                                               |

| T0-08 | Dependency drift, an unreviewed install script, or a vulnerable/native transitive silently changes the executable graph.      | Exact direct pins, lockfile v3 integrity entries, strict explicit `allowScripts` decisions, `npm ci`, direct licence/register parity, full and production audits, SBOM, and release manifest. npm and browser caches are repository-namespaced.                        | `npm run dependencies:check`; `npm audit --audit-level=high`; `npm audit --omit=dev --audit-level=high`; `npm run release:metadata`.          |
| T0-09 | A TCP-open but stale or wrong service is accepted by Playwright.                                                              | Playwright uses fixed port 4212; reuse requires a validated repository PID record, live command nonce, and exact loopback listener; readiness validates transformed app content.                                                                                       | `scripts/run-playwright.mjs`; Playwright configuration contract test.                                                                         |
| T0-10 | A working-tree pass is presented as release evidence or leaks a host path/terminal control sequence.                          | Clean capture refuses dirty state and records commit/status; diagnostic and clean commands are distinct; captured logs normalize the repository path and ANSI sequences; support claims remain pending until clean CI.                                                 | `npm run evidence:verify-all`; `npm run evidence:clean-verify`; support-matrix semantics.                                                     |
| T0-11 | A slow or abusive loopback client consumes the fixture server indefinitely.                                                   | Bounded request, header, keep-alive, and per-socket limits; GET/HEAD allowlist; no request bodies or user persistence.                                                                                                                                                 | Fixture-server configuration review and semantic health probe.                                                                                |
| T0-12 | Shutdown or partial startup leaves a misleading healthy remainder.                                                            | Serialized lifecycle lock, transactional rollback of services started in the failed operation, readiness flips before close, bounded TERM/KILL only after renewed ownership validation.                                                                                | `npm run dev:down && npm run dev:up && npm run dev:health`; lifecycle integration suite.                                                      |

## Residual risk and response

- Another process running as the same OS user can inspect argv and repository files. Tier 0 does not claim multi-user host isolation; a future packaged application must use operating-system process and IPC primitives rather than this development control plane.
- Vite and Playwright are development-only attack surfaces with relevant advisory history. They remain loopback-only, exact-pinned, audited, and absent from the emitted browser runtime.
- A hostile local process can deny service by occupying a reserved port. The safe response is diagnostic failure, never signalling or automatic remapping. See ADR-0001 and assumption A-0003.
- Automated source and bundle scans cannot prove the absence of every dynamically constructed egress path. Tier 1 must encode the document-egress invariant in a protocol/type boundary and attack it with named property and fault-injection tests before any document byte exists.
- The generated smoke PDF is a lifecycle fixture, not parser coverage or evidence that any PDF attack is detected. The support matrix keeps all PDF behavior unimplemented.

## Change triggers

Update or supersede this model before adding any document input, parser, worker message protocol, browser file API, persistent store, external URL, credential, deployment endpoint, telemetry destination, or public origin. Each new entry point requires size/time/concurrency limits, explicit refusal behavior, observable failure, and named tests before it can be used by a production slice.
