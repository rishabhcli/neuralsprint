# Direct Dependency Register

- **Register schema:** 1
- **Observed:** 2026-08-09
- **Source of package list:** direct `dependencies` and `devDependencies` in `package.json`
- **Version policy:** exact direct versions; transitive versions must be pinned by `package-lock.json`
- **Production bundle rule:** only packages imported by the browser application may ship; development packages must not enter `dist/`

This is a point-in-time supply-chain record, not a permanent safety claim. Maintenance classifications are a dated human review of the pinned release line. Security observations combine the committed full-graph and production-graph `npm audit` gates with historical advisory review. A passing locked-graph audit means only that npm reported no unresolved finding at the configured high-or-critical threshold when the evidence was generated; it does **not** cover unpublished issues, malicious releases, or all lower-severity findings.

## Resolved-graph and audit policy

Direct-package review is necessary but insufficient. The release gate must also:

1. install only with `npm ci` from committed lockfile version 3;
2. run `npm audit --audit-level=high` over the full graph;
3. run `npm audit --omit=dev --audit-level=high` over the runtime graph;
4. generate an SBOM and release manifest before a deployable artifact exists;
5. inspect install scripts, optional platform packages, licences, and provenance on every direct upgrade;
6. keep Vite, Vitest, and Playwright bound to `127.0.0.1`, because historical advisories disproportionately affect development-server trust boundaries;
7. regenerate this register when `package.json` changes.

`package.json#allowScripts` records an explicit decision for every resolved package with an install lifecycle, while npm's project-level `strict-allow-scripts=true` turns any unreviewed script into an install failure. The current policy denies `fsevents` lifecycle execution across both locked optional versions: its Darwin-only native rebuild hook is unnecessary because the tarballs contain the reviewed prebuilt binding. `npm run dependencies:check` fails if an install-script dependency appears, disappears, changes coverage, or lacks an explicit boolean decision.

An audit reporting zero known vulnerabilities means only that the registry's current advisory set did not match the resolved graph. It is not proof of absence.

## Cost measurement policy

Source-package size is intentionally not published: it is not download size, browser transfer size, parse cost, or retained heap. The current release manifest publishes exact emitted asset bytes from immutable build inputs. A future compressed-size or runtime-cost claim must be regenerated by a committed command that records, at minimum:

- emitted bytes per asset;
- gzip and Brotli bytes;
- source-map treatment;
- cold parse/evaluation timing on each supported device class;
- Playwright browser/cache disk use separately from shipped artifacts.
